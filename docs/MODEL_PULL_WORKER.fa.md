# دریافت مدل از پنل و Worker

در پنل HTTPS مدیر کل، نام مدل Ollama و Worker ثبت‌شده انتخاب می‌شود. Master فقط یک job فعال برای هر Worker می‌پذیرد، نام مدل را اعتبارسنجی می‌کند و job را در پایگاه داده ذخیره می‌کند. Worker هر ۳۰ ثانیه با هویت گره و TLS 1.3 کار را دریافت می‌کند، درخواست `POST /api/pull` را به Ollama خصوصی خودش می‌فرستد، جریان پیشرفت را می‌خواند و گزارش می‌دهد. heartbeat هم‌زمان در حلقهٔ اصلی ادامه پیدا می‌کند. پنل هر ۱۵ ثانیه وضعیت و درصد را تازه می‌کند. پس از قطع عامل، job پس از پنج دقیقه بی‌گزارشی به صف برمی‌گردد؛ retry و شکست در پنل دیده می‌شود.

فقط SuperAdmin دارای `profile.manage` می‌تواند job بسازد یا فهرست آن را ببیند. گره Edge و Worker قطع یا باطل‌شده نمی‌توانند job اجرا کنند؛ درخواست‌های گره فقط از TLS مستقیم معتبر پذیرفته می‌شوند. این مسیر برای **دریافت مدل** است و Ollama نصب‌شده را پیش‌فرض می‌گیرد؛ نصب خود برنامهٔ Ollama، حذف مدل، محدودیت ظرفیت دیسک، لغو job و سیاست انتخاب مدل در گام‌های بعدی است.

آزمون واحد رجیستری شامل احراز هویت، نقش، منع نام مخرب، پیشرفت، تکرار و بازیابی است. آزمون HTTP روی TLS معتبر و آزمون جریان ساختگی Ollama نیز اضافه شده‌اند. آزمون عملی دریافت مدل روی Worker واقعی و نمایش آن در پنل مدیر پیش از افزایش درصد پیشرفت لازم است.

استقرار ۲ اکتبر ۲۰۲۶: commit 25e3212 روی Master و Worker خصوصی نصب شد؛ ۵۳ آزمون Python روی Master موفق، سرویس TLS و عامل Worker فعال، heartbeat همراه مدل qwen3:0.6b برقرار و درخواست بدون نشست به API مدیریت مدل با 401 رد شد. دریافت واقعی یک مدل جدید و مشاهدهٔ پیشرفت با نشست مدیر هنوز اجرا نشده است.

برای آزمون عملی بدون وارد کردن رمز پنل، از شل root همان Master (فقط شبکهٔ خصوصی) می‌توان python3 -m omniops.model_admin --node-id <NODE_ID> --model qwen3:0.6b اجرا کرد. درخواست به نام system:local-root ممیزی می‌شود و همان صف و گزارش پنل را به کار می‌گیرد. این فرمان از API عمومی قابل اجرا نیست.
