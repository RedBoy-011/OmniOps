# اجرای آزمایشی هسته روی اوبونتو و اتصال ایجنت ویندوز

این دستورها برای **آزمون یک هستهٔ توسعه** هستند. سرور فعلی فقط روی `127.0.0.1:9000` گوش می‌دهد؛ پورت ۹۰۰۰ اوبونتو را روی اینترنت باز نکنید. برای اتصال از ویندوز از تونل SSH استفاده کنید. در این حالت مرورگر و ایجنت ویندوز به `http://127.0.0.1:19000` وصل می‌شوند و ترافیک تا سرور اوبونتو در SSH رمز می‌شود. این مسیر به دامنه، Caddy یا WireGuard نیاز ندارد؛ استقرار نهایی هنوز پیاده‌سازی نشده است.

## ۱. روی اوبونتو، در یک ترمینال Bash

```bash
sudo apt update
sudo apt install -y git curl python3 openssh-server
git clone https://github.com/RedBoy-011/OmniOps.git
cd OmniOps

curl -fsSL https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
. "$HOME/.nvm/nvm.sh"
nvm install 24
cd web/app && npm ci && npm run build && cd ../..

export OMNIOPS_API_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export OMNIOPS_SIGNING_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(48))')"
python3 -m omniops.bootstrap && python3 -m omniops.server
```

ساخت مدیر کل نام کاربری، موبایل و گذرواژهٔ ۱۲ تا ۱۰۲۴ نویسه را تعاملی می‌گیرد. تا زمانی که پیام موفقیت همراه با نام کاربری ظاهر نشود، مدیر ساخته نشده است. رمز کوتاه یا دو رمز نابرابر دوباره پرسیده می‌شوند؛ خطای نام کاربری/موبایل یا وجود مدیر قبلی با خروج غیرصفر پایان می‌یابد. دستور `&&` سرور را فقط پس از ساخت موفق مدیر اجرا می‌کند؛ خود سرور نیز بدون مدیر فعال شروع نمی‌شود. برای ورود دقیقاً همان نام کاربریِ پیام موفقیت را بنویسید. این ترمینال را برای اجرای سرور باز نگه دارید. کلیدهای تصادفی فقط در محیط همین ترمینال‌اند؛ با بستن آن برای اجرای بعدی باید کلید امضای خود را به شیوهٔ امن نگهداری و دوباره تنظیم کنید. تغییر کلید، نشست‌های قبلی را باطل می‌کند. کلیدها و گذرواژه را در GitHub ثبت نکنید. راهنمای نصب پایدار و مدیریت کلید هنوز ساخته نشده است.

## ۲. روی ویندوز، در یک PowerShell دیگر

مقادیر `UBUNTU_USER` و `SERVER_IP` را جایگزین کنید و تونل را باز نگه دارید:

```powershell
ssh -p SSH_PORT -N -o ExitOnForwardFailure=yes -L 127.0.0.1:19000:127.0.0.1:9000 UBUNTU_USER@SERVER_IP
```

در مرورگر ویندوز `http://127.0.0.1:19000` را باز کنید و با مدیر کل وارد شوید. از بخش «اتصال موقت ایجنت ویندوز» کد شش‌رقمی بگیرید. در **برنامهٔ نصب‌شدهٔ OmniOps Windows Edge** آدرس هسته را `http://127.0.0.1:19000` بگذارید و کد را وارد کنید. Chrome با نشانی `file:///.../omniops-web-preview/index.html` فقط پیش‌نمایش فایل‌های وب است و فرمان‌های Tauri برای اتصال به هسته را اجرا نمی‌کند.

برای بررسی سلامت تونل، در PowerShell دیگری اجرا کنید:

```powershell
Invoke-RestMethod http://127.0.0.1:19000/health
```

پاسخ مورد انتظار `status: up` و `mode: local-development` است. کد دو دقیقه اعتبار دارد؛ پس از انقضا کد جدید بگیرید. خروج از ایجنت باید ارتباط را قطع کند و بازکردن دوبارهٔ برنامه نیازمند کد تازه باشد.

## محدودهٔ آزمون چت

جفت‌سازی، پنل و آزمون خروج به Ollama نیاز ندارند. چت تا زمانی که Ollama روی همان اوبونتو یا روی یک میزبان داخلیِ در دسترس نصب و دست‌کم یک مدل در آن بارگذاری نشده باشد، پاسخ موفق نمی‌دهد. سرور فعلی ارائه‌دهندهٔ بیرونی، SOCKS و استقرار عمومی HTTPS ندارد. برای استقرار دائمی یا دسترسی کلاینت‌های دیگر، ابتدا TLS، مدیریت کلید و تنظیمات سرویس باید تکمیل شوند.
