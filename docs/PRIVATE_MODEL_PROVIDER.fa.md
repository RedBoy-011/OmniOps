# مدیریت مدل و Provider در شبکهٔ خصوصی

- پنل Master روی نشانی خصوصی `https://<master-private-ip>:9443` با CA معتبر باز می‌شود. مسیر HTTP روی پورت ۹۰۰۰ کلید API، تنظیمات SOCKS و مدیریت گره را نمی‌پذیرد. هیچ پنل اینترنتی در این مرحله مستقر نمی‌شود.
- از کارت Worker، مدل Ollama را دریافت کنید، پیشرفت را ببینید یا مدل نصب‌شده را با تأیید صریح حذف کنید. حذف از job احرازشدهٔ Worker عبور می‌کند و نتیجهٔ نامعلوم بعد از قطع Worker خودکار تکرار نمی‌شود؛ موجودی را بررسی کنید. حذف تنها مدل چت ممکن است پاسخ‌گویی چت را قطع کند.
- از بخش Provider، OpenAI، Gemini یا Anthropic را انتخاب کنید، کلید API را ثبت کنید، برای هر کدام direct یا `socks5h://<private-ip>:<port>` بگذارید و «تست اتصال و دریافت مدل‌ها» را بزنید. SOCKS5h نام دامنهٔ مقصد را در پراکسی حل می‌کند و در صورت خرابی به direct برنمی‌گردد. فقط IP خصوصی پراکسی و بدون اعتبارنامه پذیرفته می‌شود.
- بعد از تست موفق Provider را فعال کنید و برای مدل کشف‌شده قیمت ورودی و خروجی را به **دلار آمریکا به ازای هر یک میلیون توکن** به‌صورت دستی وارد کنید. این قیمت‌ها هنوز برای تخمین/سیاست ذخیره می‌شوند؛ مصرف واقعی، سهمیهٔ فروشنده و مسیر چت هیبریدی هنوز به Provider وصل نشده‌اند. تعرفه را از حساب خودتان تأیید کنید.
- کلید در دیتابیس با Fernet و کلیدی مشتق‌شده از `OMNIOPS_SIGNING_KEY` رمزگذاری می‌شود؛ مقدار کلید از API، فهرست و audit برنمی‌گردد. فایل `master.env` و کلید امضا باید مالکیت و دسترسی محدود داشته باشند؛ تغییر signing key، کلیدهای ثبت‌شده را غیرقابل بازیابی می‌کند. در Ubuntu پیش‌نیاز `python3-cryptography` است و updater آن را در صورت نبود نصب می‌کند.
- مقصد سرویس‌های API به hostnameهای رسمی این سه Provider محدود است؛ نشانی دلخواه برای جلوگیری از دسترسی ناخواستهٔ سرور به شبکهٔ داخلی در این مرحله وارد نمی‌شود. درخواست واقعی به Provider فقط با اقدام مدیر در «تست اتصال» ارسال می‌شود. به اتصال حساب واقعی بدون کلید تستی دسترسی نداریم.
