# مرکز فرماندهی گره‌ها و مسیریابی مدل OmniOps

این سند قرارداد اجرایی برای داشبورد Admin، چت وب و ایجنت ویندوز است. تصویرهای AI Studio مرجع چیدمان‌اند؛ نمایش «آنلاین»، درصد سلامت، موجودی توکن یا اتصال هر سرویس فقط وقتی مجاز است که هسته آن را واقعاً اندازه‌گیری یا از API معتبر دریافت کرده باشد. تاریخ تصویب هر قابلیت در آزمون استقرار ثبت می‌شود.

## اصل معماری

- Master Control Plane همیشه میزبان ورود، پروفایل، سیاست داده، فهرست گره‌ها، صف کارهای مدیریتی، رجیستری مدل و OmniRoute است؛ پردازش سنگین و دانلود مدل روی Master اجرا نمی‌شوند. خرابی یک Worker نباید ورود، داشبورد یا ثبت درخواست را از کار بیندازد.
- Worker Compute موتورهایی مانند Ollama و مدل‌های دیگر را اجرا می‌کند؛ Worker RAG سرویس اسناد و embedding را میزبانی می‌کند؛ Edge در استقرار عمومی TLS و دسترسی از بیرون را فراهم می‌کند. امکان افزودن چند Worker از هر نوع وجود دارد.
- Ollama و Providerهای API «منبع مدل» هستند؛ JEV/AnythingLLM «سرویس دانش»، و n8n/Langflow «سرویس گردش کار» محسوب می‌شوند. وضعیت و مجوز هر دسته جداگانه است؛ در گراف به‌عنوان مدل زبانی جا زده نمی‌شوند.
- روشن‌ماندن Master معادل تضمین پاسخ چت نیست. اگر همهٔ مدل‌های مجاز قطع شوند، داشبورد و خطای شفاف در دسترس می‌مانند. برای پاسخ‌دهی هنگام قطع Worker اصلی، باید یک مدل جایگزین روی Worker مستقل یا Provider مجازِ دیگر فراهم شود؛ «۱۰۰٪ همیشه در دسترس» بدون افزونگی و آزمون قطع قابل ادعا نیست.

## مدل داده و وضعیت واقعی

| شیء | دادهٔ ضروری | منبع مشاهده |
|---|---|---|
| گره | شناسه، نوع، نسخه، توانایی‌ها، CPU/RAM/GPU/دیسک، آخرین heartbeat | گزارش امضاشدهٔ عامل همان گره؛ گذشت زمان => stale/offline |
| سرویس | نوع، گرهٔ میزبان، زمان پاسخ، وضعیت، خطای آخر | probe دوره‌ای از Master یا عامل گره |
| Provider | local/API، حالت direct/SOCKS، وضعیت تست، خطای آخر، محدودهٔ دادهٔ مجاز | رجیستری + نتیجهٔ درخواست تست واقعی |
| مدل | provider، شناسه، modality، context، کیفیت/هزینهٔ تنظیم‌شده، وضعیت، ظرفیت | کشف API و تنظیمات نسخه‌دار مدیر |
| سهمیه | حد مصرف سازمان/کاربر، مصرف ثبت‌شده، rate limit گزارش‌شده، زمان بازتنظیم | شمارندهٔ خودمان و در صورت وجود پاسخ مستند Provider |
| تصمیم مسیر | شناسهٔ درخواست، مدل انتخابی، علت، گزینه‌های ردشده، نوع fallback | رویداد ممیزیِ بدون کلید و محتوای خصوصی |

وضعیت‌های گره `healthy/degraded/offline/unknown` هستند. اتصال UI به Master با HTTP 200 به معنی سلامت Worker یا مدل نیست. برچسب‌های نمودار و latency باید از endpoint واقعی بیایند؛ گرهٔ تعریف‌نشده یا سرویسی که هنوز probe نشده `unknown` نمایش داده می‌شود. هیچ IP خصوصی محیط کاربر در مخزن ثبت نمی‌شود.

## قرارداد OmniRoute برای چت وب و ویندوز

هر دو کلاینت از یک API و یک تصمیم‌گیر سمت Master استفاده می‌کنند. درخواست شامل `mode: auto|manual`، `model_id` در حالت manual، سقف خروجی، قابلیت لازم (متن/ابزار/تصویر)، سیاست داده و اختیار fallback است. کاربر در چت نام مدل انتخاب‌شده و دلیل انتخاب/تعویض را می‌بیند. Admin همان تصمیم را با جزئیات بیشتر، خطا و میزان مصرف در پنل می‌بیند.

1. **فیلتر قطعی:** مجوز کاربر و سازمان، ممنوعیت خروج سند، نوع قابلیت، سلامت، موجودی واقعی مدل، محدودیت بودجه و شرط SOCKS بررسی شوند. حالت `local_only` هر مدل ابری را حذف می‌کند، حتی اگر محلی قطع باشد.
2. **انتخاب auto:** میان گزینه‌های مجاز با وزن قابل تنظیم برای تناسب کار، کیفیت ثبت‌شده، هزینه، تأخیر، بار گره و ترجیح محلی امتیاز بدهد. مدل گران یا ابری فقط با سیاست مجاز انتخاب شود. دلیل انتخاب ذخیره و نمایش داده شود.
3. **انتخاب manual:** مدل مشخص‌شده pin می‌شود. در حالت پیش‌فرض، قطع یا اتمام سهمیهٔ همان مدل خطای مشخص می‌دهد؛ فقط با گزینهٔ روشن «اگر در دسترس نبود جابه‌جا شو» و در محدودهٔ سیاست همان درخواست fallback می‌کند.
4. **مصرف و سهمیه:** `context_remaining` (پنجرهٔ مدل)، `rate_limit_remaining` (RPM/TPM)، `org_budget_remaining` و اعتبار پولی Provider چهار مفهوم جدا هستند. مقدار ناشناخته `نامشخص` نمایش داده می‌شود؛ از حدس عددی استفاده نمی‌شود. قبل از ارسال، بودجهٔ خروجی رزرو و بعد از پاسخ با مصرف گزارش‌شده تسویه شود.
5. **خطا و سوئیچ:** timeout، 429 با `Retry-After`، قطع Worker و circuit breaker مسیر بعدی مجاز را فعال می‌کنند؛ تعداد تلاش و زمان کل محدود است. پس از ارسال بخشی از پاسخ استریم یا اجرای یک ابزار دارای اثر جانبی، تکرار خودکار فقط با منطق ایمنِ همان درخواست مجاز است. جابه‌جایی از محلی به ابر بدون اجازهٔ سیاست و کاربر انجام نمی‌شود.

**مسیر موقت مرحلهٔ اول:** اگر تنها Ollama فعال باشد، auto بهترین مدل محلیِ مجاز را انتخاب می‌کند و در نبود آن خطای قابل فهم می‌دهد. برچسب «هوشمند هیبریدی» پس از اتصال واقعی حداقل دو منبع، مصرف و آزمون fallback فعال می‌شود.

## صفحه‌های Admin و چت

- «گره‌ها و سرویس‌ها»: کارت‌های Master/Worker/Edge با سلامت، منابع و زمان آخرین گزارش؛ نمودار ارتباط که فقط اتصالات واقعی ثبت‌شده را ترسیم می‌کند؛ کلیک برای جزئیات probe و تاریخچهٔ خطا. برای شبکهٔ فعلی، نبود Edge عمومی حالت `تعریف نشده` دارد.
- «راه‌اندازی محلی»: ثبت Worker مجاز، بررسی پیش‌نیاز، نصب Ollama روی Worker، پیشرفت واقعی دانلود مدل، راه‌اندازی، تست مدل و قابلیت ادامهٔ مشاهدهٔ job پس از بستن صفحه. فرمان دلخواه root از پنل وجود ندارد؛ عامل نصب روی Worker فقط عملیات از پیش تعریف‌شده را اجرا می‌کند.
- «Provider و مدل‌ها»: افزودن Ollama/موتور داخلی/API، تنظیم direct یا SOCKS برای هر Provider، نگهداری کلید خارج از UI و لاگ، تست اتصال، کشف فهرست مدل، هزینه/اولویت/محدودیت داده، غیرفعال‌سازی و نمایش موجودی سهمیه با سطح اطمینان.
- «سیاست مسیریابی»: وزن‌های auto، ترجیح محلی، سقف بودجهٔ هر سازمان/پروفایل، fallback مجاز، ترتیب کانال‌ها و حالت شبیه‌سازی تصمیم بدون ارسال پیام واقعی.
- «چت پنل و ایجنت»: انتخاب «هوشمند» یا مدل مشخص، وضعیت مدل و ارتباط، نشان‌دادن مسیر انتخاب‌شده و علت تغییر، خطاهای تفکیک‌شدهٔ شبکه/سهمیه/مجوز. تنظیمات مدیریتی فقط در Admin؛ ایجنت و چت کاربر فقط گزینه‌های مجاز همان پروفایل را می‌بینند.

## ترتیب ساخت و معیار پذیرش

1. **حقیقت عملیاتی و Worker محلی:** ثبت امن Worker، heartbeat و probe واقعی؛ نصب Ollama/مدل با job پایدار، درصد واقعی و آزمون چت. Master در حین دانلود مدل پاسخ ورود و سلامت بدهد؛ قطع Worker و بازگشت آن در داشبورد مشخص شود.
2. **رجیستری مشترک:** مدل‌های محلی در یک فهرست پایدار، API لیست و انتخاب یکسان در چت وب و ایجنت؛ انتخاب manual و auto فقط محلی با علت تصمیم. نبود مدل پیام روشن دهد.
3. **Provider و سهمیه:** دست‌کم یک API واقعی علاوه بر Ollama، direct/SOCKS قابل آزمون، کلید ایمن، دادهٔ مجاز، اندازه‌گیری مصرف و نمایش «نامشخص» برای سهمیهٔ غیرقابل اندازه‌گیری. تست جابه‌جایی بر اثر 429 و قطع شبکه.
4. **داشبورد گراف و خدمات دیگر:** نمودار واقعی گره‌ها، تاریخچهٔ سلامت، اضافه‌کردن RAG/اتوماسیون به‌صورت adapter، نه جعل مدل یا وضعیت. هر کارت باید به جزئیات اندازه‌گیری‌شده برسد.
5. **استقرار عمومی و تاب‌آوری:** Edge با دامنه و TLS، تونل/شبکهٔ خصوصی، پشتیبان‌گیری، دو مسیر مستقل پاسخ مدل، آزمون قطع Worker و بازیابی Master. تنها پس از این مرحله وعدهٔ تداوم پاسخ قابل سنجش است.

در هر مرحله، آزمون پذیرش روی سرور واقعی، چت وب و ایجنت ویندوز شرط اعلام درصد جدید است. تصاویر AI Studio هدف تجربهٔ کاربری‌اند، نه مدرک وجود سرویس‌های عملیاتی.
