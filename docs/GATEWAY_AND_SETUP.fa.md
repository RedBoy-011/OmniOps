# قرارداد عملیاتی درگاه و راه‌اندازی

## مسیر درخواست مدل

`کاربر/کلاینت → احراز هویت و پروفایل → سیاست داده → انتخاب مهارت/عامل → انتخاب مدل واجد شرایط → Provider → ثبت مصرف و نتیجه`

درگاه اصلی OmniOps آدرس `/v1` و کلید کلاینت صادر می‌کند. در نخستین انتشار، فقط مسیرهایی که واقعاً پیاده‌سازی و آزموده شده‌اند در مستند API اعلام می‌شوند. پنل مدیریتی هویت و مجوز جدا از کلید مصرف مدل دارد.

در حالت هوشمند، ابتدا سیاست سخت اعمال می‌شود: مدل باید روشن، سالم، دارای ظرفیت و پشتیبان قابلیت موردنیاز (ابزار/تصویر/متن) باشد؛ دادهٔ «فقط محلی» هیچ‌گاه به Provider بیرونی نمی‌رود. سپس امتیاز سلامت، تأخیر، ظرفیت و هزینه برای انتخاب بین گزینه‌های مجاز به کار می‌رود. اگر Jev فعال باشد، فقط از میان گزینه‌های مجاز پیشنهاد می‌دهد؛ نبود یا خطای آن به انتخاب قطعی محلی بازمی‌گردد. 9Router در صورت نصب یک upstream اختیاری است و حق تغییر سیاست خروج داده ندارد.

## شبکهٔ Provider

| نوع | مسیر | شرط |
|---|---|---|
| Ollama و مدل داخلی | آدرس خصوصی ثبت‌شده | بدون خروج از شبکهٔ داخلی |
| API بیرونی مستقیم | TLS به دامنهٔ مجاز Provider | تأیید سیاست سازمان و فعال‌سازی صریح |
| API بیرونی از SOCKS | پراکسی ثبت‌شده با DNS از سمت پراکسی | آزمون اتصال؛ هنگام خطا بدون بازگشت پنهانی به مستقیم |

رمز API و پراکسی فقط سمت سرور نگهداری می‌شود. فرم پنل مقدار ذخیره‌شده را دوباره آشکار نمی‌کند. آزمون Provider زمان، وضعیت، نام مدل‌های کشف‌شده و خطای واقعی را نشان می‌دهد.

## راهنمای اولین اجرا

1. تعیین مدیر اصلی و رمز اختصاصی؛ ساخت سازمان واحد.
2. تعیین حالت شبکهٔ داخلی یا Edge؛ در حالت Edge نصب‌کننده نام دامنهٔ عمومی را می‌پرسد، DNS و مسیر خصوصی تا Master را بررسی می‌کند، Caddy را پیکربندی می‌کند و صدور/تمدید خودکار TLS و پاسخ HTTPS را می‌آزماید. تا موفقیت این مرحله، نشانی HTTP عمومی برای ورود یا جفت‌سازی اعلام نمی‌شود.
3. افزودن Ollama/مدل محلی و آزمون فهرست مدل‌ها.
4. اختیاری: افزودن Provider بیرونی، انتخاب مستقیم یا SOCKS و آزمون اتصال.
5. ایجاد پروفایل‌های چت، مهارت، ابزار، درخواست و تأیید اقدام برای ۱۰ مدیر.
6. ثبت نخستین دستگاه ویندوز و مشاهدهٔ تله‌متری واقعی.
7. اجرای یک سناریوی مشاهده و یک راه‌اندازی دوبارهٔ سرویس با تأیید.

تمام مراحل وضعیت «انجام نشده/موفق/خطا» و راه برگشت دارند. نصب بستهٔ ایجنت و مدل از پنل تنها پس از آزمون واقعی، همراه با فضای لازم و نتیجهٔ نصب، عرضه می‌شود.
