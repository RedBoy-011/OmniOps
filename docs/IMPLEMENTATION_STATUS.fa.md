# وضعیت پیاده‌سازی نسخهٔ مستقل

تاریخ: ۲ اکتبر ۲۰۲۶. این سند بعد از هر تحویل عملی به‌روز می‌شود.

## انجام‌شده و آزموده‌شده

- تعریف محصول برای یک سازمان و ۱۰ مدیر؛ پروفایل‌های ترکیبی چت، مهارت، ابزار، درخواست و تأیید.
- قواعد مستقل مجوز و محدودهٔ ابزار/دستگاه؛ تأییدکنندهٔ جداگانه به عنوان پیش‌فرض.
- قواعد انتخاب مدل: ممنوعیت خروج دادهٔ محلی، احراز قابلیت مدل، تشخیص سلامت و عدم بازگشت SOCKS به مسیر مستقیم.
- اتصال واقعی Python به API محلی Ollama برای کشف مدل و چت غیرجریانی؛ پاسخ خطا به‌جای نتیجهٔ ساختگی.
- درگاه آزمایشی روی loopback یا نشانی صریح LAN خصوصی با کلید اجباری و مسیرهای واقعی `/v1/models` و `/v1/chat/completions`، بدون مسیر اینترنتی برای Ollama.
- ۳۷ آزمون موفق با کتابخانهٔ استاندارد Python: ثبت‌نام pending، تأیید، کد اتصال یک‌بارمصرف، چت ایجنت، heartbeat و ابطال، در کنار Ollama و درگاه مدل.
- فرم React کشویی شیشه‌ای و اعلان درخواست‌های منتظر پس از ورود مدیر، متصل به API؛ build فرانت‌اند موفق.
- پنجرهٔ شناور Tauri/React با شش خانهٔ PIN، تأیید خودکار، ناحیهٔ کشیدن پنجره و چت، build فرانت‌اند موفق؛ توکن در فرمان‌های Rust از WebView جدا شده است. پاسخِ چتِ در جریان پس از خروج به نشست بعدی نمایش داده نمی‌شود.
- اجرای GitHub Actions روی Runner ویندوز: `cargo check`، ساخت نصب‌کنندهٔ NSIS بدون امضا و بارگذاری artifact همراه SHA256 موفق؛ فایل دانلودشده با checksum تطبیق داده شد. کاربر نصب و اتصال ایجنت روی دستگاه ویندوز را گزارش کرد؛ آزمون نصب تمیز و سه کار عملیاتی هنوز انجام نشده‌اند.
- پیش‌نمایش HTML پنل فارسی با نمای موبایل در CSS. مشاهدهٔ بصری در مرورگر این محیط هنوز انجام نشده است.

- Master و Worker مجزا در شبکهٔ خصوصی آزموده شدند: نصب Ollama از بستهٔ رسمی با checksum، یک مدل سبک، فهرست مدل، چت واقعی و قطع/وصل Worker بدون از دست رفتن سلامت Master. اصلاح مهلت استنتاج پس از مشاهدهٔ خطای بارگذاری سرد انجام شد.
- ابزار تشخیص فقط‌خواندنی و اسکریپت نصب Worker به مخزن افزوده شدند؛ کلیدها و پایگاه داده در به‌روزرسانی Master حفظ شدند.

## گام‌های اجرایی بعدی

1. تبدیل ساخت مدیر اولیه از CLI به راهنمای اولین اجرا و امکان ویرایش بعدی پروفایل‌های ۱۰ مدیر.
2. تکمیل آزمون نصب تمیز Tauri، هویت دستگاه، رویداد خروج نشست ویندوز و نصب‌کنندهٔ معتبر.
3. ارتقای API آزمایشی `/v1` به سرویس عملیاتی با کلیدهای محدود به پروفایل، استریم و ثبت مصرف واقعی.
4. اتصال فرم Provider به API؛ ذخیرهٔ محرمانهٔ کلید، آزمون واقعی و مسیر SOCKS برای سرویس بیرونی.
5. گزارش واقعی CPU/RAM/دیسک و وضعیت سرویس و شبکه از Windows Agent.
6. چرخهٔ وظیفهٔ ساختاریافته برای restart سرویس، تأیید پروفایل و گزارش ممیزی، همراه با آزمون روی Windows واقعی.
7. بسته‌بندی هسته و ایجنت، آزمون نصب تمیز، دستور نصب تک‌خطی با نشانی نهایی مخزن، سپس انتشار نسخه.
8. بعد از نسخهٔ پایه: مهارت‌ها، Workerهای بیشتر، Jev/9Router اختیاری، Edge/WireGuard و MCP واقعی.

## وضعیت انتشار

مخزن عمومی مستقل `RedBoy-011/OmniOps` روی `main` توسعه می‌یابد. آزمون Python و وب و ساخت نصب‌کنندهٔ NSIS در GitHub Actions اجرا می‌شوند؛ وضعیت هر commit باید از همان اجرای مربوط بررسی شود. Master واقعی به‌روزرسانی و Worker واقعی با مدل سبک و قطع/وصل سرویس آزموده شدند؛ کلیدها و دیتابیس Master حفظ شدند. نصب‌کنندهٔ ویندوز هنوز امضا نشده و استقرار عمومی Edge، آزمون نصب تمیز و امنیت ارتباط چندگرهی باقی است. هیچ کلید API یا توکن در مخزن ثبت نشده است.
