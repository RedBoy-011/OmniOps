# برنامهٔ توسعهٔ OmniOps به فضای کاری عامل‌محور

مبنای بازنگری: ۳ اکتبر ۲۰۲۶. این سند خواسته‌های پیوست کاربر دربارهٔ گفت‌وگو، کدنویسی، ترمینال، Git، وب، مرورگر، کنترل رایانه، اسناد، خروجی بصری، مهارت‌ها، MCP، چندعامل، زمان‌بندی و امنیت را به برنامهٔ محصول تبدیل می‌کند. این‌ها **هدف توسعه** هستند؛ اشارهٔ پیوست به توانایی ابزارهای دیگر به معنی وجود همان توانایی در OmniOps نیست. معیار درصد و دروازه‌های پذیرش در [نقشهٔ پیشرفت](PROGRESS_ROADMAP.fa.md) است. [تطبیق نقشهٔ ده‌فازی](AGENT_10_PHASE_REVIEW.fa.md) ترتیب ابزار، Sandbox، فناوری و شواهد فعلی را روشن می‌کند.

## وضعیت تحویل و مرز محصول

- **موجود و مستقر در Master خصوصی:** هویت و سطح دسترسی، چت وب با مدل محلی و Provider برگزیده، مسیر SOCKS، پروژهٔ شخصی، پیش‌نویس وظیفه، یادداشت حافظهٔ حساب و ذخیرهٔ اختیاری تاریخچه. پیوست‌های محدود متن/تصویر در پروژه از وب ذخیره و حذف می‌شوند و هیچ پیوستی به مدل ارسال نمی‌شود. ایجنت جفت‌سازی، چت، پروژه و پیش‌نویس وظیفه دارد؛ نصب ایجنت جدید و پذیرش تصویری با مدیر/عضو هنوز باز است. Master در LAN روی HTTPS خصوصی ۹۴۴۳ آزمون سلامت شده است.
- **فاصلهٔ اصلی:** هیچ حلقهٔ عامل اجرایی، sandbox ابزار، ویرایش فایل واقعی، اجرای فرمان با تأیید، مرورگر هوشمند، Git اجرایی، تولید سند، زمان‌بند پایدار یا عامل فرعی عملیاتی پذیرفته نشده است. پیش‌نویس وظیفه فرمان اجرا نمی‌کند. ادعای پوشش کامل تا عبور از آزمون دستگاه/کاربر و امنیت ممنوع است.
- **محدودهٔ نخستین انتشار:** یک سازمان با حدود ۱۰ مدیر و اعضای دارای پروفایل؛ Master مسئول سیاست و ممیزی، Worker مسئول مدل و بار سنگین، ایجنت ویندوز مسئول دسترسی محلی انتخاب‌شده. وب به فایل‌های رایانهٔ کاربر مستقیم دسترسی ندارد. Edge عمومی، چندسازمانی و کنترل بدون حضور کاربر در گام‌های متأخر می‌مانند.

## قرارداد معماریِ مشترک

`Chat / Workspace UI → Task API → Orchestrator → Model Router + Context Manager + Permission Engine + Tool Registry + Skills Loader + Memory + Event Stream → Worker / Windows Agent / approved connectors`.

هر کار رکورد پایدار با `owner, project, mode, goal, steps, status, scope, approvals, artifacts, audit` دارد. مدل می‌تواند پاسخ یا درخواست ابزار ساختاریافته بدهد؛ Orchestrator در **هر نوبت** مجوز ابزار، محدودهٔ پروژه، سقف هزینه/زمان و رضایت خروج داده را بررسی می‌کند؛ اجراگر محدود نتیجه را برمی‌گرداند؛ رویدادها و artefactها به کاربر نشان داده می‌شوند. پایان، توقف، تلاش دوباره و شکست باید حالت صریح داشته باشند. مدل و متن Prompt به‌تنهایی مجوز اجرا نیستند؛ هیچ فراخوانی ابزار مستقیماً از خروجی آزاد مدل وارد Shell نشود. سیاست Worker/Agent در مرز اجرا اعمال شود؛ قطع Master یا از دست رفتن مجوز باعث توقف اقدام تازه شود.

## وابستگی‌های اجرای محصول

۱. پذیرش HTTPS خصوصی با مدیر/عضو و نصب ایجنت Windows، سپس تکمیل پیوست در کادر گفتگو و ایجنت و رضایت خروج داده. ۲. تعریف Task API، رویداد، سیاست و اجراگر محدود پیش از ساخت هر ابزار Shell/Git/Browser. ۳. ارائهٔ بستهٔ کوچک کارهای روز اول و ابزار خواندن/آزمون کد، سپس نوشتن و اقدام تأییدشده. ۴. اسناد/RAG/Khoj اختیاری و مهارت/MCP بعد از تفکیک مالک و سیاست ابزار. ۵. چندعامل و زمان‌بندی پس از پایداری اجرای تک‌عامل، حسابرسی و توقف. ۶. Edge عمومی فقط بعد از دامنه، TLS، کلید یکتای میزبان‌ها، آزمون بازیابی و مرور تهدید.

Khoj تنها پایلوت ایزولهٔ موتور دانش است؛ جایگزین مالکیت هویت، Task API یا سیاست ابزار Master نمی‌شود. Coucou مرجع تجربهٔ شناور ایجنت و رابط فارسی است؛ استفاده از کد یا وابستگی آن منوط به بررسی مجوز و انتساب در نسخهٔ منتشرشده است. هیچ موتور/مهارت خارجی بدون ارزیابی مجوز و مالکیت داده به هسته تحمیل نشود.
