# استقرار TLS خصوصی Master و عامل محدود Worker

وضعیت در ۲ اکتبر ۲۰۲۶: کد این مرحله در مخزن آمادهٔ آزمون است؛ هنوز روی دو سرور واقعی اجرا نشده. پنل فعلی HTTP روی Master دست‌نخورده می‌ماند. هدف این مرحله افزودن HTTPS مستقیم روی IP خصوصی Master، پورت جداگانه و heartbeat از Worker است؛ اتصال Edge اینترنتی و Caddy در فاز جدا انجام می‌شود.

## پیش‌نیاز شبکه و اعتماد

- Master: `172.19.30.100`، Worker: `172.19.30.99`. در فایروال Master فقط **TCP 9443 از Worker و آدرس‌های مدیر قابل اعتماد** مجاز شود. پورت 9443 روی اینترنت عمومی باز نشود. HTTP فعلی روی 9000 فعلاً برای سازگاری کلاینت موجود می‌ماند و برای مجوز گره قابل استفاده نیست.
- در Master باید نصب فعلی `omniops-master.service` سالم و کد مخزن به‌روز باشد. روی Worker، Python 3، OpenSSL و systemd لازم است. هر دو اسکریپت باید از پوشهٔ مخزن OmniOps اجرا شوند.
- گواهی ریشهٔ داخلی فقط برای آزمایش شبکهٔ خصوصی ساخته می‌شود. کلید خصوصی CA و کلید Master هرگز از Master خارج نشوند. فقط `ca.crt` عمومی از مسیر مدیریتی منتقل و هش SHA-256 آن از یک مسیر مستقل و مورد اعتماد با خروجی Master تطبیق داده شود. چون کلیدهای میزبان SSH دو سرور طبق آزمون قبلی یکسان بودند، برای انتشار اینترنتی باید یکتا شوند؛ تطبیق هش CA در این مرحله جلوی اتکا به فایل انتقالی بدون احراز را می‌گیرد.

## مرحلهٔ ۱: Master

در پوشهٔ مخزن فعال روی Master، ابتدا به‌روزرسانی متعارف و آزمون سلامت HTTP انجام شود. سپس با کاربر root:

```bash
bash scripts/install-private-master-tls.sh
```

اسکریپت پورت جدا را می‌پرسد (پیش‌فرض 9443). برای اجرای غیرتعاملی `OMNIOPS_TLS_PORT=9443` قابل استفاده است. یک CA داخلی و گواهی با SAN برابر IP خصوصی Master می‌سازد، آن را با OpenSSL بررسی می‌کند و سرویس مستقل `omniops-master-tls.service` را راه می‌اندازد. بررسی `/health` با اعتماد به CA و تطبیق IP انجام می‌شود؛ هیچ گزینهٔ نادیده‌گرفتن گواهی استفاده نمی‌شود. تایمر روزانه فقط وقتی گواهی نزدیک پایان اعتبار باشد آن را با همان CA تعویض می‌کند. مسیر CA عمومی: `/etc/omniops/private-pki/ca.crt`؛ مسیر کلیدها محرمانه و `0600` است. اگر سرویس تازه خطا بدهد، HTTP قبلی باقی می‌ماند.

برای آزمایش دستی از همان Master:

```bash
curl --noproxy '*' --cacert /etc/omniops/private-pki/ca.crt https://172.19.30.100:9443/health
systemctl status omniops-master-tls.service
```

مرورگر ویندوز فقط پس از واردکردن CA به مخزن اعتماد سیستم/مرورگر و تطبیق اثرانگشت می‌تواند پنل HTTPS را بدون هشدار باز کند؛ این واردکردن در این مرحله خودکار نیست. تا پیش از آن، صدور مجوز از CLI امن Master انجام می‌شود:

```bash
python3 -m omniops.node_admin --master https://172.19.30.100:9443 --ca-file /etc/omniops/private-pki/ca.crt --role worker
```

نام کاربری و گذرواژهٔ SuperAdmin در ورودی تعاملی گرفته می‌شوند؛ پس از تأیید، مجوز یک‌بارمصرف را فقط برای انتقال به Worker نمایش می‌دهد. آن را در تاریخچهٔ shell یا فایل دائمی ثبت نکنید. صدور مجوز روی HTTP رد می‌شود.

## مرحلهٔ ۲: Worker

فایل عمومی `ca.crt` را به Worker منتقل کنید و هش SHA-256 همان فایل را با خروجی Master تطبیق دهید. در پوشهٔ مخزن به‌روز روی Worker، با کاربر root:

```bash
bash scripts/install-private-worker-node.sh
```

نصاب نشانی `https://172.19.30.100:9443`، مسیر فایل CA و هش مورد اعتماد را می‌پرسد. اول گواهی و سلامت Master را بررسی می‌کند؛ سپس یک کاربر سیستمی محدود می‌سازد، کد سبک را به `/opt/omniops-node` کپی می‌کند، مجوز یک‌بارمصرف را در ورودی مخفی می‌گیرد و **پس از heartbeat موفق** سرویس `omniops-worker-node.service` را فعال می‌کند. فایل هویت گره `0600` است. اجرای دوباره هویت موجود را حفظ می‌کند و به Master دیگری منتقلش نمی‌کند. رمز مدیر و grant را در متغیر محیطی یا دستور خط فرمان قرار ندهید.

برای دیدن وضعیت:

```bash
systemctl status omniops-worker-node.service
journalctl -u omniops-worker-node.service -n 30 --no-pager
```

پس از آزمون، فهرست گره‌های ثبت‌شده و آخرین CPU/RAM/دیسک و مدل‌های محلی در پنل **HTTPS** مدیر نمایش داده می‌شود. روی HTTP کنونی بخش مدیریت گره‌ها غیرفعال است. مجوز Edge فقط پس از تهیهٔ سرور و دامنه و طراحی تونل امن صادر شود.

## دروازهٔ پذیرش

- تست نصب تازه و اجرای دوباره بدون بازتولید CA/هویت، با گواهی و IP معتبر؛ رد گواهی، IP و نقش اشتباه.
- ثبت گره از یک بار مصرف، heartbeat و بازیابی پس از قطع اتصال و چرخش اعتبارنامه؛ ابطال گره و رد heartbeat بعدی.
- حفظ سلامت HTTP Master در شکست TLS و قطع Worker؛ هیچ دستور root از درخواست شبکه اجرا نشود.
- بررسی فایروال، دسترسی فایل‌ها و لاگ‌ها روی هر دو میزبان؛ سپس ثبت نتیجه در درصد پیشرفت.

تا تکمیل این آزمون‌ها، درصد پیشرفت کل تغییر نمی‌کند.
