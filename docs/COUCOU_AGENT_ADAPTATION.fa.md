# تطبیق رفتار ایجنت OmniOps با مرجع Coucou

مرجع بررسی‌شده: سورس `Louis-CFM/coucou`، به‌ویژه `windows/src/island/fsm.ts`، `windows/src/core/layout.ts` و `windows/src-tauri/src/tray.rs`. کاربر یک نسخهٔ محلی از این مرجع برای بررسی رابط ارائه کرد.

## مرز استفاده

کد Coucou تحت MIT است. نام Coucou و Mochi، کاراکتر و شکل‌ها/انیمیشن‌های آن، آیکون‌ها، صداها و تصاویر طبق `LICENSE-ASSETS.md` برای بازنشر در برنامهٔ دیگر آزاد نیستند. رابط این مرحله با برند، آیکون و انیمیشن اختصاصی OmniOps پیاده می‌شود و سورس یا دارایی‌های Coucou کپی نشده است؛ ایدهٔ پنجرهٔ جمع‌شونده و مسیر آیکون کنار ساعت مرجع رفتاری بوده‌اند. اگر کدی از مرجع در آینده منتقل شود باید اعلان حق نشر MIT همان بخش همراهش باشد.

## رفتار ویندوز

| رفتار در OmniOps | اجرا/وضعیت |
|---|---|
| پنجرهٔ باز با ورود PIN و گفت‌وگو | PIN و نشست موقت Rust موجود؛ صفحهٔ باز دارای نمای کلی و گفتگو است. |
| جمع‌شدن پس از اتصال | دکمهٔ «جمع کردن» پنجره را به حالت کوچکِ قابل کلیک تغییر می‌دهد؛ کلیک دوباره آن را باز می‌کند. |
| آیکون کنار ساعت | Tauri Tray با نشان مستقل OmniOps؛ کلیک چپ نمایش/پنهان، منوی راست نمایش/پنهان/قطع ارتباط و خروج. |
| دکمهٔ «−» | پنجره را پنهان می‌کند و فرایند/heartbeat در حافظه ادامه دارد. |
| دکمهٔ «×» و خروج از Tray | برنامه را پایان می‌دهد، نشست Rust پاک می‌شود و ابطال سرور تلاش می‌شود؛ در نبود شبکه lease سرور منقضی می‌شود. |
| وضعیت مدل/ابزار | تا تکمیل API عملیاتی با دادهٔ ساختگی نمایش داده نمی‌شود؛ کارت ابزار به‌صراحت در حال توسعه است. |

آزمون پذیرش بعدی روی ویندوز واقعی: پیداشدن آیکون در ناحیهٔ اعلان (گاهی زیر پیکان ^)، بازگشت پنجره با کلیک، حفظ نشست هنگام پنهان‌سازی، تغییر اندازهٔ مناسب روی نمایشگرهای کوچک، و قفل‌شدن پس از «قطع ارتباط و خروج».

## گام بعدی رابط عملیاتی

بعد از آزمون رفتار ایجنت، صفحهٔ تعاملی سرور عملیاتی برای ثبت گره خصوصی، سلامت واقعی CPU/RAM/GPU، وضعیت Ollama و مدل‌های موجود، آزمون اتصال و سیاست بار بین Master و Worker ساخته می‌شود. تنظیمات ذخیره‌شدهٔ گره جای IP ثابت در کد را می‌گیرند. تا زمانی که API و احراز هویت گره پیاده و آزموده نشوند، این بخش «آماده» یا «متصل» نشان داده نمی‌شود.
