# هویت گره‌های Worker و Edge (بخش آمادهٔ آزمون)

تا ۲ اکتبر ۲۰۲۶، کد هستهٔ صدور مجوز و رجیستری گره نوشته و به API وصل شده است. روی Master داخلیِ فعلی که HTTP دارد، همهٔ مسیرهای این بخش با پاسخ `426` بسته‌اند؛ **هیچ مجوزی را روی HTTP ارسال نکنید**. فرم صدور و ابطال گره و مشاهدهٔ heartbeat در پنل آماده است، اما روی HTTP داخلی پنهان می‌ماند؛ این مرحله هنوز به نصب‌کنندهٔ سه‌نقشی یا سرور واقعی متصل نشده و در درصد استقرار منظور نشده است.

## قرارداد API

Master فقط در صورتی مسیرهای زیر را اجرا می‌کند که اتصال ورودی **مستقیماً TLS 1.3** باشد؛ مقدار `X-Forwarded-Proto` پذیرفته نمی‌شود. برای TLS مستقیم باید مسیر گواهی و کلید خصوصی معتبر در `OMNIOPS_TLS_CERT` و `OMNIOPS_TLS_KEY` تنظیم شوند. هر دو میزبان باید اعتبار گواهی و نام Master را مستقل بررسی کنند؛ از `curl -k` یا نادیده‌گرفتن خطای گواهی استفاده نمی‌شود. قرار دادن Caddy بدون TLS بین آن و Master باعث فعال‌شدن این API نمی‌شود؛ TLS سرتاسری یا تونل با TLS داخلیِ معتبر لازم است.

- `POST /api/admin/nodes/grants` با Bearer نشست SuperAdmin و بدنهٔ `{"role":"worker"}` یا `edge`: خروجی `id`، `grant` و `expires_at`. مجوز ۲۵۶ بیت تصادفی است، ۱۰ دقیقه اعتبار دارد، فقط هش کلیددارش ذخیره می‌شود و یک بار مصرف می‌شود. نمایش آن فقط در پاسخ صدور است.
- `POST /api/admin/nodes/grants/revoke` با `{"id":"..."}`: ابطال مجوز مصرف‌نشده.
- `POST /api/nodes/enroll` با `{"grant":"...","name":"worker-01"}`: خروجی `id`، `role`، `credential` و `credential_expires_at`. نقش گره فقط از مجوز صادرشده خوانده می‌شود. اعتبارنامه ۳۰ روزه است و فقط هش کلیددارش در Master می‌ماند؛ گره باید مقدار دریافتی را فقط روی همان میزبان با دسترسی فایل `0600` نگه دارد.
- `POST /api/nodes/heartbeat` با `{"id":"...","credential":"...","metrics":{"version":"1.0","cpu_percent":12,"ram_percent":45,"disk_percent":56,"models":["qwen3:0.6b"]}}`: آخرین حضور را ثبت می‌کند؛ داده‌های اختیاری محدود و راستی‌آزمایی می‌شوند.
- `POST /api/nodes/rotate` با `{"id":"...","credential":"...","next_credential":"..."}`: اعتبارنامهٔ قدیم را به‌صورت اتمیک با مقدار تصادفی جدیدی که گره پیش‌تر در فایل امن خود ذخیره کرده جایگزین می‌کند. در صورت قطع شبکه، گره با اعتبارنامهٔ جدید و سپس قدیم وضعیت را بازیابی می‌کند.
- `POST /api/admin/nodes/revoke` با `{"id":"..."}`: گره را غیرفعال می‌کند و اعتبارنامهٔ آن بلافاصله رد می‌شود.
- `GET /api/admin/nodes`: فهرست گره‌ها، وضعیت ابطال، انقضای اعتبارنامه و آخرین heartbeat، بدون هیچ مقدار محرمانه.

نصب عامل سبک Worker با دسترسی محدود به‌صورت سرویس، آزمون نمایش داده‌های گره در پنل روی TLS واقعی، گزارش مرحله‌های نصب و سیاست نگهداری تله‌متری در گام بعدی است. آزمون TLS واقعی در CI لینوکس اجرا می‌شود. نصب‌کنندهٔ خودکار نباید از این API تا آزمون گواهی معتبر استفاده کند. دروازهٔ پیش از انتشار اینترنتی شامل چرخش رمزهای افشاشده و یکتاسازی کلید میزبان SSH است.

## اجرای آزمایشی عامل سبک روی Worker لینوکس

بعد از آماده‌شدن TLS 1.3 معتبر روی نشانی خصوصی Master، نصب کد در همان مسیر پروژه و صدور grant در پنل/ابزار مدیریتی آینده، از روی Worker اجرا شود:

```bash
python3 -m omniops.node_client --state "$HOME/.local/share/omniops/node-identity.json" --ca-file /path/to/master-ca.pem enroll --master https://PRIVATE_MASTER_IP:9000 --name worker-01
python3 -m omniops.node_client --state "$HOME/.local/share/omniops/node-identity.json" --ca-file /path/to/master-ca.pem heartbeat
python3 -m omniops.node_client --state "$HOME/.local/share/omniops/node-identity.json" --ca-file /path/to/master-ca.pem run
```

مقدار مجوز در ورودی مخفی ترمینال وارد می‌شود؛ در خط فرمان، تاریخچهٔ shell و فایل تنظیمات ثبت نشود. فایل هویت با مجوز `0600` ساخته و خوانده می‌شود و عامل باید با کاربر محدود اجرا شود. اگر CA در مخزن گواهی سیستم موجود باشد، `--ca-file` لازم نیست. گواهی Master باید نام یا IP خصوصی واردشده را در SAN داشته باشد؛ TLS نامعتبر یا نشانی عمومی رد می‌شود. عامل فقط CPU، RAM، دیسک و نام مدل‌های Ollama محلی را گزارش می‌کند و فرمان root از شبکه اجرا نمی‌کند.

اسکریپت‌های جداگانهٔ TLS خصوصی Master و سرویس محدود Worker در [راهنمای استقرار دو گره](PRIVATE_LAN_TLS_WORKER.fa.md) آماده شده‌اند. نصب یکپارچهٔ سه‌نقشی، پیشرفت نصب مدل از پنل و آزمون قطع/بازیابی روی دو ماشین هنوز انجام نشده‌اند. اتصال گره روی HTTP فعلی همچنان عمداً مسدود است.
