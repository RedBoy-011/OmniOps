## 📜 شناسنامه و فلسفه هسته مرکزی: OmniOps

### 🔹 مفهوم بنیادین: سیستم مدیریت عملیات همه‌جانبه (Comprehensive Operations Management System)
نام **OmniOps** فراتر از یک عنوان تجاری، نمایانگر معماری، وسعت و هویت یکپارچه این پلتفرم است. این سیستم به عنوان یک **«دپارتمان IT خودمختار»** (Autonomous IT Department)، مرزهای سنتی میان توسعه‌دهنده نرم‌افزار (**Dev**) و مدیر زیرساخت (**Ops**) را از بین می‌برد و هر دستوری را از یک گفتگوی ساده، به یک اقدام فیزیکی روی سرور و سیستم‌عامل تبدیل می‌کند.

### 🔹 کالبدشکافی نام‌گذاری
* **Omni (فراگیر و همه‌جانبه):** نماد یکپارچگی سیستم است. این پلتفرم به یک مدل یا رابط خاص محدود نیست؛ بلکه تمام مدل‌های هوش مصنوعی (ابری و محلی)، کدهای RAG و تمام درگاه‌های کاربری را به صورت متمرکز درک و مدیریت می‌کند.
* **Ops (عملیات و اجرا):** نماد قدرت اجرایی سیستم است. OmniOps صرفاً یک چت‌بات پاسخگو نیست، بلکه یک بازوی عملیاتی است که کد می‌نویسد، سرویس‌ها را اجرا می‌کند و زیرساخت را به صورت زنده مدیریت می‌نماید.

### 🔹 اکوسیستم و درگاه‌های ارتباطی
هسته مرکزی OmniOps برای دریافت و اجرای دستورات، از یک شبکه ارتباطی چندلایه بهره می‌برد:
1. **داشبورد ویندوزی (Glassmorphism UI):** اتاق فرمان مرکزی (Master Control Room) با قابلیت مانیتورینگ بلادرنگ منابع سخت‌افزاری، پایانه دستورات، تاییدیه اقدامات حساس (Approval Gate) و حالت دسترسی کامل (Full Access Mode).
2. **ایجنت سیار اندرویدی (Mobile Node):** کلاینت همراه با اتصال امن مستقیم یا کد جفت‌سازی ۶ رقمی موقت و چراغ وضعیت زنده (LED Presence) که کنترل کامل پروژه‌ها را از هر کجا میسر می‌سازد.
3. **درگاه شناختی مرکزی (Contextual Memory & Handoff):** خلاصه‌سازی هوشمند لاگ‌ها و کدها بدون اتلاف توکن، همراه با انتقال بی‌وقفه مکالمه (Handoff) میان اندروید، ویندوز و هسته پردازشی.

> **API شناسه سیستم:** تمامی کلاینت‌ها شناسنامه رسمی و معماری زنده هسته را از مسیر `GET /api/system/identity` دریافت می‌کنند.

## 🏛 معماری کلاستر ۳ گرهی (3-Node Cluster Architecture)

سیستم به گونه‌ای مهندسی شده که سازمان‌ها بتوانند با حداکثر امنیت و بدون وابستگی انحصاری به سرورهای ابری خارجی، یک بستر کاملاً توزیع‌شده داشته باشند:

```
                                  ┌───────────────────────────────┐
                                  │   اینترنت عمومی / راه دور     │
                                  └───────────────┬───────────────┘
                                                  │ HTTPS / WSS
                                                  ▼
                                    ┌───────────────────────────┐
                                    │    نود آینه (Edge Node)   │
                                    │  • سرور لینوکس ابری (VPS) │
                                    │  • Caddy + Let's Encrypt  │
                                    │  • وب‌سوکت آنی Unbuffered │
                                    └─────────────┬─────────────┘
                                                  │ تونل امن اینترنتی
                                                  ▼ (IP استاتیک شرکت)
┌─────────────────────────────────────────────────────────────────────────────────┐
│                           شبکه داخلی شرکت (Local LAN)                            │
│                                                                                 │
│   ┌───────────────────────────────────┐     ┌─────────────────────────────────┐ │
│   │    نود هسته مرکزی (Master Node)   │     │    نود پردازشی (Worker Node)    │ │
│   │  • اوبونتو سرور محلی              │     │  • سرور قدرتمند / GPU           │ │
│   │  • PostgreSQL 16 (کاربران/سشن‌ها) │◄───►│  • موتور استنتاج Ollama / vLLM  │ │
│   │  • Redis 7 (صف و PubSub)          │     │  • داکر سندباکس اجرای ایزوله کد │ │
│   │  • Qdrant Vector DB (حافظه RAG)   │     │  • فال‌بک به پردازش بهینه CPU/RAM│ │
│   │  • LiteLLM & FastAPI Core Engine  │     └─────────────────────────────────┘ │
│   └─────────────────▲─────────────────┘                                         │
│                     │                                                           │
│         ┌───────────┴───────────┐                                               │
│         ▼                       ▼                                               │
│  ┌───────────────┐     ┌─────────────────┐                                      │
│  │ کلاینت ویندوز │◄───►│ کلاینت اندروید  │                                      │
│  │ (Tauri + C++  │     │ (PWA + Pairing  │                                      │
│  │  + React RTL) │     │  LED وضعیت زنده)│                                      │
│  └───────────────┘     └─────────────────┘                                      │
└─────────────────────────────────────────────────────────────────────────────────┘
```

1. **سرور هسته مرکزی (Master Node - Ubuntu Server محلی):**
   - مرکز فرماندهی و مغز سامانه شامل PostgreSQL 16، Redis 7، دیتابیس برداری Qdrant، درگاه LiteLLM و ارکستراتور تسک‌ها.
   - دسترسی با پینگ صفر در شبکه داخلی شرکت (`http://192.168.x.x:8000`) و پورت فوروارد برای اتصال از بیرون.
2. **سرور عملیاتی محاسباتی (Worker Node - Ubuntu Server با منابع بالا / GPU یا CPU):**
   - اجرای مدل‌های سنگین لوکال (Ollama / vLLM)، محیط سندباکس امن برای تست ایزوله کدها، و پایش سخت‌افزار.
   - اتصال به کلاستر تنها با دادن IP سرور مستر و `Cluster Secret Key`.
3. **سرور آینه اینترنتی (Edge / Mirror Node - لینوکس VPS در اینترنت):**
   - معکوس‌کننده پروکسی Caddy با اخذ خودکار گواهینامه رایگان Let's Encrypt و فوروارد بدون بافرینگ وب‌سوکت‌ها.
   - فراهم‌کننده دسترسی ایمن به سامانه از خارج از محیط شرکت از طریق دامنه (`https://ai.example-corp.com`).

## 🔌 ماتریس پورت‌های پیش‌فرض و فایروال (Port Matrix)

هنگام نصب هر نود، اسکریپت به صورت تعاملی از شما می‌پرسد که آیا مایل به استفاده از پورت پیش‌فرض هستید (با زدن کلید Enter) یا می‌خواهید پورت سفارشی خود را تعیین کنید:

| نود (Node) | پورت پیش‌فرض | پروتکل | کاربرد و توضیحات | وضعیت فایروال | امکان تغییر هنگام نصب؟ |
|---|---|---|---|---|---|
| **Master Node** | **`8000`** | TCP | هسته مرکزی API، وب‌سوکت ارکستراتور و پنل وب | باز در شبکه داخلی (LAN) | ✅ بله (پرسش تعاملی یا متغیر `OMNIOPS_BIND_PORT`) |
| Master (کانتینر داکر) | `5432` | TCP | پایگاه داده کاربران و سشن‌ها (PostgreSQL 16) | ایزوله در شبکه داکر | در فایل `.env` |
| Master (کانتینر داکر) | `6379` | TCP | صف تسک‌ها و Pub/Sub وضعیت‌ها (Redis 7) | ایزوله در شبکه داکر | در فایل `.env` |
| Master (کانتینر داکر) | `6333` | TCP | پایگاه داده برداری حافظه کدهای RAG (Qdrant) | ایزوله در شبکه داکر | در فایل `.env` |
| Master (کانتینر داکر) | `4000` | TCP | هسته درگاه مدیریت مدل‌ها (LiteLLM) | ایزوله در شبکه داکر | در فایل `.env` |
| **Worker Node** | **`11434`** | TCP | درگاه استنتاج مدل‌های محلی Ollama | باز در شبکه داخلی (LAN) | ✅ بله (پرسش تعاملی یا متغیر `OLLAMA_PORT`) |
| Worker ➔ Master | **`8000`** | TCP | ارسال تسک‌ها و گزارش سلامت به سرور هسته | خروجی به LAN | ✅ بله (پرسش تعاملی یا متغیر `MASTER_PORT`) |
| **Edge Node** | **`80`** | TCP | چالش خودکار اخذ گواهی SSL (Let's Encrypt ACME) | باز در اینترنت عمومی | الزامی برای پروتکل ACME |
| **Edge Node** | **`443`** | TCP | پورت امن عمومی اینترنتی HTTPS و WSS (وب‌سوکت) | باز در اینترنت عمومی | ✅ بله (پرسش تعاملی یا متغیر `EDGE_HTTPS_PORT`) |
| Edge ➔ فایروال شرکت | **`8000`** | TCP | پورت فوروارد شده سرور مستر روی IP استاتیک شرکت | پورت فوروارد فایروال | ✅ بله (پرسش تعاملی یا پارامتر سوم) |

> 💡 **نکته معماری در مورد نود آینه (Edge Node) - VPS سبک در برابر هاست اشتراکی (cPanel/DirectAdmin):**  
> نسخه آینه (Edge) باید **حتماً روی یک سرور مجازی لینوکسی فوق‌العاده سبک (حتی با ۱ هسته CPU و ۱ گیگابایت رم)** با وب‌سرور Caddy اجرا شود و **استفاده از هاست‌های اشتراکی (مانند cPanel یا DirectAdmin) از نظر معماری کاملاً غیر اصولی است.** وب‌سرور Caddy تنها حدود ۱۵ تا ۲۰ مگابایت رم و ۰.۱٪ سی‌پی‌یو مصرف می‌کند اما از وب‌سوکت‌های دوطرفه و استریم زنده بدون بافرینگ (`unbuffered flush`) پشتیبانی کامل دارد؛ در حالی که هاست‌های اشتراکی به دلیل محدودیت‌های تایم‌اوت Apache/PHP و بافر کردن پاسخ‌ها، ارتباط استریم هوش مصنوعی را قطع یا مسدود می‌کنند.

## ⚡ نصب تک‌خطی سرورها (One-Line Installers)

تمامی اسکریپت‌های زیر مستقیماً از مخزن رسمی **`RedBoy-011/OmniOps`** فراخوانی می‌شوند و وابستگی‌ها، داکر، تنظیمات امنیتی، فایروال و فایل‌های `.env` را به صورت کاملاً خودکار پیکربندی می‌کنند:

### ۱. نصاب هوشمند و یکپارچه کلاستر (پیشنهادی)
یک دستور برای راه‌اندازی هر یک از ۳ نود با منوی تعاملی فارسی:
```bash
curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/scripts/quick-install.sh | sudo bash
```

---

### ۲. نصب اختصاصی سرور هسته مرکزی (Master Node)
بر روی سرور اوبونتو در شبکه محلی شرکت اجرا کنید:
```bash
curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/master/install-master.sh | sudo bash
```
> **عملکرد خودکار:** داکر و کامپوز را نصب کرده، از شما می‌پرسد که آیا مایل به تغییر پورت پیش‌فرض (8000) هستید یا خیر (با زدن اینتر پورت 8000 تایید می‌شود)، کلیدهای امنیتی کلاستر (`CLUSTER_SECRET_KEY`) را تولید می‌کند و کانتینرها را بالا می‌آورد.

---

### ۳. نصب اختصاصی سرور پردازشی محاسباتی (Worker Node)
بر روی سرور پردازشی (دارای کارت گرافیک یا پردازنده چند‌هسته‌ای) اجرا کنید:

**حالت تعاملی (پرسش آدرس مستر، کلید و پورت‌ها):**
```bash
curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/worker/install-worker.sh | sudo bash
```

**حالت مستقیم با آرگومان (نمونه آدرس‌های فرضی و آموزشی):**
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/worker/install-worker.sh) <MASTER_LAN_IP> "<CLUSTER_SECRET_KEY>" [MASTER_PORT] [OLLAMA_PORT]
```
*مثال با مقادیر فرضی:*
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/worker/install-worker.sh) 192.168.1.100 "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855" 8000 11434
```

---

### ۴. نصب اختصاصی سرور آینه و پروکسی اینترنتی (Edge Node)
بر روی یک VPS لینوکسی سبک (۱ هسته CPU و ۱ گیگ رم) متصل به اینترنت عمومی اجرا کنید:

**حالت تعاملی (پرسش دامنه، آی‌پی استاتیک و پورت‌ها):**
```bash
curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/edge/install-edge.sh | sudo bash
```

**حالت مستقیم با آرگومان (نمونه مقادیر فرضی و استاندارد):**
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/edge/install-edge.sh) <DOMAIN> <COMPANY_STATIC_IP> [TARGET_PORT] [EDGE_PORT]
```
*مثال با مقادیر فرضی:*
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/RedBoy-011/OmniOps/main/cluster/edge/install-edge.sh) ai.example-corp.com 203.0.113.50 8000 443
```
> **نکته:** آی‌پی فرضی `203.0.113.50` و دامنه `ai.example-corp.com` نمونه‌های آزمایشی و فرضی هستند. شما در زمان نصب، آی‌پی استاتیک واقعی شرکت و دامنه اینترنتی خود را وارد می‌کنید.

## 🖥 کلاینت دسکتاپ ویندوز (Windows Desktop Agent)

کلاینت دسکتاپ اختصاصی با **Tauri v2 + Rust + React** و معماری فوق‌مدرن بر پایه تجربه **Google Antigravity**:

<div align="center">
  <kbd>Ctrl+V الصاق تا ۵ عکس</kbd> • <kbd>گیت تایید ۳ حالته با دسترسی کامل</kbd> • <kbd>تولید پین‌کد ۶ رقمی موبایل</kbd> • <kbd>پایش سخت‌افزار با فال‌بک صریح CPU</kbd>
</div>

### ویژگی‌های کلیدی:
* **رابط کاربری بلورین و دارک عمیق (Deep Dark Glassmorphism):** ۱۰۰٪ راست‌چین (RTL) با استفاده از تایپوگرافی اصیل **وزیرمتن (Vazirmatn)**.
* **گیت تاییدیه‌های ۳ حالته:**
  * 🔒 *دستی (Manual):* نیاز به تایید تک‌تک دستورات شل و فایل‌ها توسط کاربر.
  * ⚡ *خودکار (Auto):* تایید خودکار دستورات ایمن و رید-آنلی.
  * 👑 *دسترسی کامل (Full Access):* اجرای پیوسته تمامی دستورات بدون توقف و وقفه با مسئولیت کاربر.
* **پیوست پیشرفته تصاویر با کلیپ‌بورد:** امکان فشردن همزمان `Ctrl+V` و چسباندن تا سقف **۵ تصویر** در محیط چت و حذف تک‌تک پیش‌نمایش‌ها.
* **مدال جفت‌سازی با موبایل (Short-Code Pairing):** تولید کد ۶ رقمی امن با تاریخ انقضای ۵ دقیقه‌ای جهت اتصال اپلیکیشن اندروید.
* **پایشگر سخت‌افزار و فال‌بک هوشمند CPU:** نمایش زنده مصرف رم، سی‌پی‌یو و دیسک، همراه با اعلان صریح در صورت نبود پردازنده گرافیکی:
  > *«این سیستم فاقد کارت گرافیک است (پردازش‌ها به صورت بهینه روی CPU و RAM با موفقیت انجام می‌شوند)»*
* **مرکز مدل‌های لوکال (Local Models Hub):** نمایش لیست مدل‌های Ollama به همراه درصد پیشرفت زنده دانلود (Progress Bar).

### راه‌اندازی و بیلد کلاینت ویندوز:
```powershell
# ورود به پوشه کلاینت ویندوز
cd agent/windows-edge

# نصب پکیج‌های فرانت‌اند
npm install

# اجرای حالت توسعه و زنده
```

## 📱 اپلیکیشن همراه اندروید (Android Mobile Companion)

کلاینت همراه برای پایش از راه دور، ارسال تسک‌ها به سیستم ویندوزی و ارتباط لحظه‌ای:

```
┌────────────────────────────────────────────────────────┐
│  📁 پروژه فعلی: omniops-core ▾     [گفت‌وگو | وظیفه]   │
│                                  🟢 ایجنت ویندوز متصل  │
├────────────────────────────────────────────────────────┤
│  ⚡ پردازش مستقیم: روی ویندوز اجرا خواهد شد           │
├────────────────────────────────────────────────────────┤
│                                                        │
│  [کاربر]                                               │
│  تست‌های واحد پروژه را اجرا کن و خروجی را بررسی کن.    │
│                                                        │
│  [OmniOps Assistant]                                   │
│  دستور با موفقیت روی ایجنت دسکتاپ ویندوز اجرا گردید.  │
│  ✓ ارسال و اجرا روی ویندوز                            │
│  ⚡ کش پرامپت: ۱۱۸۰ توکن    🛡️ صرفه‌جویی RTK: ۳۱.۲٪   │
│                                                        │
└────────────────────────────────────────────────────────┘
```

### ویژگی‌های کلیدی:
* **چراغ LED وضعیت اتصال به ویندوز:** یک نشانگر سبز چشمک‌زن ملایم در هدر موبایل که وضعیت زنده بودن ایجنت دسکتاپ را نمایش می‌دهد (`🟢 ایجنت ویندوز متصل است`).
* **ورود دوگانه:**
  * ورود فوری با وارد کردن **کد کوتاه ۶ رقمی** تولیدشده در ویندوز.
  * ورود مستقیم با نام کاربری و آدرس شبکه داخلی/اینترنتی سرور.
* **هدایت از راه دور (Remote Dispatch):** هر پرامپت، دستور یا عکسی که در گوشی فرستاده شود، مستقیماً به کامپیوتر ویندوزی ارسال شده و کارهای توسعه و اجرای کد روی ویندوز انجام می‌شود.
* **ارسال عکس تا ۵ عدد:** امکان ثبت عکس از دوربین یا گالری گوشی و الصاق به چت.
* **نشان‌های هوشمند صرفه‌جویی:** نمایش زنده توکن‌های صرفه‌جویی‌شده توسط کش پرامپت و ذخیره‌ساز RTK در زیر پیام‌ها.

## 🧠 هسته هوش مصنوعی و بهینه‌سازی توکن (OmniOps Token Engine)

تمامی قابلیت‌های پیشرفته بهینه‌سازی توکن، فشرده‌سازی خروجی ابزارها و چرخش هوشمند مدل‌ها به صورت بومی و اختصاصی در هسته پایتونی `OmniOps` توسعه داده شده است:

### ۱. کش پرامپت سازمانی (Prompt Caching)
- جلوگیری از پردازش مجدد کانتکست‌ها و متون تکراری در درخواست‌های مکرر با اثر انگشت هش SHA256.
- نتیجه: **سرعت بسیار بالاتر پاسخ‌دهی** و **کاهش چشمگیر هزینه‌های پردازش و مصرف توکن**.

### ۲. ذخیره‌ساز توکن RTK (Real-Time Token Compressor)
- فشرده‌سازی هوشمند خروجی ابزارها پیش از ارسال به مدل (مانند `git diff`، `git log`، `tree`، `ls` و گزارش‌های بیلد).
- حذف تکرارهای غیرضروری و خلاصه‌سازی ساختاریافته خروجی دستورات.
- نتیجه: **صرفه‌جویی مستقیم ۲۰٪ الی ۴۰٪ در توکن‌های مصرفی هر درخواست**.

### ۳. موتور آبشار هوشمند چندلایه (Multi-Tier Cascade Router)
چرخش خودکار و بدون توقف درخواست‌ها در صورت مواجهه با محدودیت یا خطای Rate Limit:
* **لایه ۱ (اشتراک‌های شرکتی):** مدل‌های سنگین و استدلالی (Claude 3.5 Sonnet, OpenAI Codex, Gemini 1.5 Pro).
* **لایه ۲ (مدل‌های اقتصادی ارزان):** پردازش سریع و ارزان (MiniMax, GLM-5).
* **لایه ۳ (سرویس‌های سهمیه آزاد):** پشتیبانی از ارائه‌دهندگان نامحدود آزاد و اعتبارات تخصیص‌یافته.
* **لایه ۴ محلی (کلاستر داخلی آفلاین):** استنتاج کاملاً محلی مدل‌های کلاستر پردازشی (Qwen 2.5 Coder 7B/14B, Llama 3.2).

### ۴. استخر کلیدهای مدل‌ها (Key Pool Manager)
- امکان تعریف همزمان ده‌ها API Key با چرخش خودکار بر اساس کمترین بار (Key Rotation).
- خروج خودکار کلیدهای لیمیت‌شده از مدار (Cooldown) و بازگشت خودکار آن‌ها پس از رفع محدودیت بدون قطعی سرویس.

## 🧰 مهارت‌های فارسی سازمانی (Persian Enterprise Skills)

سیستم دارای ۱۱ مهارت ماژولار با توضیحات و متادیتای کاملاً فارسی در پوشه `skills/` است:

| شناسه مهارت | عنوان فارسی | کاربرد و کارکرد |
|---|---|---|
| `omniops-core` | **هسته عملیاتی OmniOps** | بهینه‌سازی توکن، فشرده‌سازی RTK و کش پرامپت |
| `omniops-chat` | **چت و کدنویسی پیشرفته** | مکالمه چندزبانه، عیب‌یابی و معماری کدهای سنگین |
| `omniops-image` | **بینایی ماشین و تحلیل تصویر** | بررسی دیاگرام‌ها، لاگ‌های تصویری و شات‌های UI |
| `omniops-web-search` | **جستجوی هوشمند در وب** | یافتن آخرین داکیومنت‌ها، پکیج‌ها و خطاهای نرم‌افزار |
| `omniops-web-fetch` | **استخراج محتوای وب** | تبدیل صفحات فنی و مقالات به Markdown ساختاریافته |
| `omniops-embeddings` | **تولید بردار و امبدینگ** | نمایه‌سازی معنایی کدها در پایگاه برداری Qdrant |
| `omniops-stt` | **تبدیل گفتار به متن** | پردازش فرامین صوتی فارسی به متن در سیستم |
| `omniops-tts` | **تبدیل متن به گفتار** | خواندن صوتی پاسخ‌ها و هشدارهای صوتی سیستم |
| `omniops-video` | **تحلیل ویدیو و چندرسانه‌ای** | بررسی فایل‌های رسانه‌ای و لاگ‌های ویدیویی سیستم |
| `windows-computer-use` | **کنترل بومی ویندوز** | کنترل ماوس، کیبورد و فرامین سیستمی دسکتاپ |
| `system-diagnostics` | **عیب‌یابی سخت‌افزار سرور** | پایش منابع کلاستر، حافظه، شبکه، پردازنده و کارت گرافیک |

### به‌روزرسانی زنده مهارت‌ها از گیت‌هاب:
مدیر سیستم می‌تواند در هر زمان با ارسال درخواست به اندپوینت زیر، مهارت‌ها را از ریپازیتوری‌های گیت‌هاب همگام کند:
```bash
curl -X POST http://<MASTER_IP>:8000/api/skills/sync \
  -H "Content-Type: application/json" \
  -d '{"repo_url": "https://github.com/RedBoy-011/OmniOps", "branch": "main"}'
```

## 🔌 درگاه جهانی سازگار با ابزارهای کدنویسی (V1 API)

هسته `OmniOps` دارای لایه تطبیق کامل با مشخصات استاندارد OpenAI است. شما می‌توانید تمامی ابزارهای محبوبی نظیر **Claude Code**، **Cursor**، **Cline**، **Codex** یا **OpenClaw** را مستقیماً به کلاستر خود متصل کنید:

```bash
# تنظیم متغیر محیطی در ترمینال یا تنظیمات ادیتور
export OPENAI_BASE_URL="http://<MASTER_LAN_IP>:8000/v1"
export OPENAI_API_KEY="sk-omniops-enterprise"
```

* اندپوینت لیست مدل‌ها: `GET /v1/models`
* اندپوینت چت و تکمیل کد: `POST /v1/chat/completions`
